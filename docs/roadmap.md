## 工作線

- **A 線（要用客戶端，一次只能做一件）：** C1 → T1 實測 → M1 實測 → M2 實測
- **B 線（不需要客戶端，交給中階平行做）：** A6b、S1、N0、P2、X1
- **C 線（高階自己做）：** D1 多人房間模型設計稿（S1 交付後開始；PM 審查、操作者同意之後才能實作）

任務契約在 `docs/backlog.md`。

## 風險

- **M3：** 朋友的作業系統決定要用哪個 exe：Win11 用修改版，Win10 用原廠版（`reference/setup.md`「依作業系統選 exe」）。**Win7 和 Win8 完全沒有測過。**
- **M2：** PvE 是 P2P（由房主的客戶端開 Listen），加入者直接連到房主的 IP 和埠（`research/2026-09-18-d1-room-formats/`），VPN 和防火牆都要讓這條連線通。

## 開服前階段（PM 2026-09-19，依 S2 `docs/reference/system-coverage.md`）

**階段完成條件：** 該系統的 opcode ✅ 比例達標，**並且**做過一次實機驗證。只寫完 handler 不算完成。

**兩個原則：**
1. 每個階段開工前，先做該系統的唯讀格式分析，比照 D1-A、battle-host 的做法；分析要過 Sol 審查才能實作。
2. 網路研究找到的原版資料一律標明來源和可信度（官方公告／玩家記述），不能直接當規格。有衝突時，以客戶端行為為準。
