## 二、改 `mech_licenses` 的槽位順序沒有效果 ❌

用 `database/swap-test-mech-slots.js` 把帳號 5、6 的 slot 0 與 slot 5 對調
（slot 0 → `mech_type 6` ＝ `MTE_a`），然後第三段在 **08:32:24** 登入——
**晚於** DB 寫入（約 08:29–08:30）——**仍然拿到 `MOM_a`**。

排除掉的解釋：

- ❌ **伺服器快取**：`getMechLicenses`（`database/db.js:156`）每次呼叫直查 DB，
  沒有快取層；呼叫點是 `dispatch/gamelogin.dispatch.js:187` 與
  `dispatch/account.dispatch.js:489`，**都在登入流程裡**。
- ❌ **伺服器沒把順序送出去**：`SN_LICENSE_INFO`（`dispatch/account.dispatch.js:593-604`）
  就是照 `ORDER BY slot` 逐列寫 `lic.mech_type`，對調後送出的順序確實變成 6,2,3,4,5,1,7,8。

→ 🟡 **客戶端取預設機體時不照封包順序**，多半是自己照 `mech_type` 排。
這也連帶讓 explorer 先前那個「UC 內部槽位 ＝ `mech_type - 1`」的 ⬜ 假設變得更可疑，
但本輪沒有直接證據，不下結論。

**該對調已還原**（`--revert --apply`，已回到 slot 0 = `mech_type 1`）。腳本保留備用。
