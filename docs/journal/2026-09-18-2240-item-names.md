## 資料來源

`/mnt/c/Games/MetalRage Online/data/System/Cache.Bin`（484086 bytes）。

- **GameItemRecord 表**（ItemIndex → RepresentIndex、HighGroup）：沿用
  `dispatch/room.dispatch.js` 既有常數（`GAME_ITEM_RECORD_TABLE_START=0x2294`,
  stride `0x67`, count `2112`），未重新推導。
- **顯示名稱** 不在 GameItemRecord 裡，而是在另一組 `Spec*Record` 表
  （`Engine/CacheManager.uc:198-333`：`SpecMechRecord`／`SpecWeaponMainRecord`／
  `SpecWeaponSubRecord`／`SpecBoosterRecord`／`SpecSkinRecord`／`SpecPilotRecord`／
  `SpecEtcRecord`）。客戶端用哪張表查名稱由 `GetItemHighGroup(ItemIndex)` 決定，即
  `CacheManager.GetSpecItemName`（`Engine/CacheManager.uc:1289-1309`）的 switch：
  HighGroup 1=機體／2=主武器／3=副武器／4=推進器／5=駕駛員／6=塗裝／
  其他（含 7、9 消耗品類）=SpecEtcRecord；**HighGroup 8（卡片）該 `case` 被註解掉，
  客戶端拿不到卡片名稱**，這點在原始碼裡是確定的（不是本次分析的猜測）。

## 編碼

沿用 `docs/research/2026-09-18-subordination/README.md` 已確認的
FCompactIndex 長度前綴：正數＝ANSI 位元組數（含結尾 `\0`），負數＝UTF-16LE
code unit 數（含結尾 `\0`）。本次用這個規則重新獨立解析了整張 pilot 表
（25 筆），逐筆比對 `docs/research/2026-09-18-room-pilot-avatar/pilot-records-dump.txt`
（Claude 高階先前的 dump），**25 筆全部逐字元相符**，含中文姓名與
「基本駕駛員」，可視為對該 dump 的獨立覆核。

## Spec*Record 表怎麼找到的

這幾張表不是固定 offset（每筆都有變長字串欄位），彼此前後緊接（1 byte
FCompactIndex 數量 + N 筆變長 record，接著下一張表）。做法：搜尋
`SpecMechRecord` 第一筆的已知 ClassName 字串 `"ZMechanic.SA01m"` 當錨點，
往前 5 bytes（1 byte 長度前綴 + 4 byte RepresentIndex）、再往前 1 byte 拿到
數量欄，從那裡開始依序往後走：

機體(16) → 主武器(55) → 副武器(23) → 推進器(7) → 塗裝(95) → 駕駛員(25) → 其他消耗品(181)

每張表結束的 byte offset 剛好接上下一張表的數量欄，**零間隙、零重疊**，
且機體/主武器/副武器/推進器的筆數（16/55/23/7）與
`docs/journal/2026-09-16-33-weapon-model-true-root-cause-verified.md`、
`2026-09-16-34-handoff-history.md` 記錄的「Table 6/7/8/9」筆數完全吻合，
駕駛員表也和既有 pilot dump 逐字元相符 —— 多方交叉對得上，判斷這個解析是對的。

## ⚠️ 發現一個跟既有筆記不完全一致的地方（不影響本次結論，僅供意識到）

`2026-09-16-33`／`2026-09-16-34` 兩篇日誌把塗裝表標成「Table 10」，但本次
（在 `flash-wip-m3` 分支上）看到的 `docs/research/2026-09-18-room-pilot-avatar/
pilot-records-dump.txt` 也把駕駛員表標成「Table 10」——兩者標號衝突。
本次獨立解析證實**駕駛員表確實緊接在塗裝表之後**（塗裝表結尾 byte
offset 精確等於 pilot dump 記載的駕駛員表起始 offset `0x44404`），所以
駕駛員表在「表序」上應該是塗裝表的下一張（若照 `CacheManager.uc:672-696`
的宣告順序編號，駕駛員會是第 11 張，不是第 10 張）。這只是兩篇筆記對
「Table N」這個標號本身有分歧，**兩篇筆記記錄的實際資料內容都沒有錯**
（塗裝表 95 筆、駕駛員表 25 筆都各自對得上）；只是標號本身不能同時信。
中階不改判定，寫在這裡留給高階看要不要在兩篇日誌追加更正。
