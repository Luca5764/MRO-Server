# N0：讓區網第二台主機連到伺服器

**狀態：🟡 中階／待審**（Claude Sonnet 5 子 agent，任務 N0）

## 目標

同一區網的第二台主機能用 TCP 連到 WSL2 裡的 9211／30907。只做分析＋腳本，不執行、不改 Windows 設定、不重啟 WSL、不啟停伺服器。

## 現況調查（唯讀，這台機器）

- `.wslconfig`（`%USERPROFILE%\.wslconfig`，即 `/mnt/c/Users/<你的 Windows 使用者名稱>/.wslconfig`）：只有 `memory=24GB`／`swap=16GB`，沒有 `networkingMode=mirrored`——確認目前是預設 NAT 模式。
- `ip addr`：WSL2 的 `eth0` 是 `192.168.217.8/20`；`ip route` 顯示 default via `192.168.208.1`。這個網段跟 Windows 的區網完全不同，是 WSL 內部的虛擬網段。
- Windows `ipconfig /all`：實體區網卡（Realtek Gaming 2.5GbE，DHCP）是 `192.168.0.10/24`，gateway `192.168.0.1`。另外還有一張「WSL (Hyper-V firewall)」vEthernet（`192.168.208.1/20`），以及一張目前未連線的 VPN Client 虛擬網卡。
- `netsh interface portproxy show all`：空，目前沒有任何 portproxy 規則。
- `netsh advfirewall firewall show rule name=all`（過濾 9211／30907／MRO／MetalRage）：沒有任何符合的既有規則，8982 行輸出裡完全沒命中。
- Windows 版本：build 26200（遠高於 mirrored networking 需要的 22H2/22621），WSL 版本 2.6.3.0——mirrored networking 在這台機器技術上可行。

## 方案選擇：portproxy，不用 mirrored networking

兩個方案都寫進 `docs/reference/setup.md` 的取捨表了，這裡記關鍵理由：

**選 portproxy。** 決定性因素是「不能重啟 WSL」——mirrored networking 需要改 `.wslconfig` 後 `wsl --shutdown` 才生效，這會把現在跑著的伺服器 tmux session 一起殺掉，違反「不啟動或停止伺服器」的限制，也不是我（中階）能做的事。portproxy 不用重啟任何東西，設定/還原都是純 Windows 側操作。

代價是 WSL2 的 IP 每次重啟都會變（`docs/reference/setup.md` 既有的表格已經記過這點），portproxy 規則會跟著失效。但這本來就是 per-session 的操作（要跟第二台主機連線時才開），腳本每次執行都重新查詢當下的 IP，不是額外負擔。

另外這台機器有一張 VPN Client 虛擬網卡（目前未連線）。mirrored 模式下虛擬網卡／VPN 是否會被鏡像進 WSL、造成防火牆或路由規則意外命中，我沒有把握，也沒有測試環境可以驗證——這是 mirrored 方案沒選的次要理由，寫進 setup.md 供之後參考。

## 腳本

`Metal Rage Online Server/tools/win/lan-open.ps1`／`lan-close.ps1`：

- 都要求系統管理員權限（開頭檢查 `WindowsBuiltInRole.Administrator`，不是就報錯結束）。
- `lan-open.ps1` 用 `wsl.exe -- hostname -I` 抓 WSL 目前的 IP，用 `Get-NetIPAddress` 排除 `vEthernet|WSL|Loopback|Tap|VPN|Virtual` 介面自動抓區網網段（可用 `-Subnet` 覆寫），對 9211／30907 建立 `netsh interface portproxy` 轉發＋一條防火牆 inbound 規則（`RemoteAddress` 限制在該網段，`Profile` 限制 Private/Domain，不含 Public；規則名稱前綴 `MRO-LAN-`）。
- `lan-close.ps1` 反向操作：刪 9211／30907 的 portproxy 規則、刪所有 `MRO-LAN-*` 防火牆規則。
- 我沒有執行這兩支腳本，也沒有改任何 Windows 設定。只驗證了不會動系統狀態的部分：PowerShell 語法用 `[scriptblock]::Create()` 解析過（不執行 script body）；子邏輯（IP 網段位元運算、`wsl hostname -I` 輸出格式、`Get-NetIPAddress` 排除規則在這台機器上會不會抓錯介面）用獨立片段跑過，例如 `Get-NetworkCidr -IPAddress "192.168.0.10" -PrefixLength 24` 正確算出 `192.168.0.0/24`，`Get-NetIPAddress` 過濾後只剩一張「乙太網路 192.168.0.10/24」，沒有誤抓 WSL 或 VPN 介面。

## 待驗證（⬜，寫進 setup.md 了）

`netsh interface portproxy` 是代理實作還是單純 NAT，會不會保留原始來源 IP，我沒有把握也沒環境測。第一次拿兩台機器測試時，要看 session log 的 `connect` 事件 `peer` 欄位是第二台主機的真實區網 IP，還是 Windows 那張 WSL 專用虛擬網卡的 IP（這台是 `192.168.208.0/20` 網段）——如果是後者，代表 portproxy 沒保留來源位址，這是已知限制，不用去改 `server.js`。

## 操作者要做的事（精簡）

1. 以系統管理員開 PowerShell，`cd` 到 `tools/win`，跑 `.\lan-open.ps1`。
2. 第二台主機上 `Test-NetConnection <Windows 區網IP> -Port 9211` 與 `-Port 30907`，都要 `True`。
3. 客戶端 `ip=` 參數與 `MetalRage.ini`／`Default.ini` 的 `ServerIP` 都改成 Windows 的區網 IP。
4. 測完後跑 `.\lan-close.ps1` 還原。
5. 順便回報 session log 的 `peer` 欄位長什麼樣子，回答上面那個待驗證問題。
