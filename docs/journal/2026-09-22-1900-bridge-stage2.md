## 三個實機才會發現的問題（靜態檢查全部看不出來）

1. **Frida 17 拿掉了 `Module.findBaseAddress`** → `TypeError: not a function`，腳本當場死。
   改用 `Process.findModuleByName`，並保留舊 API 與 `enumerateModules` 當後備。
2. **模組是延遲載入的**：腳本在行程剛起來時執行，那時 `ZNetwork.dll` 還沒載入，
   原本的寫法一次找不到就永久放棄。改成輪詢等待（`whenModuleLoaded`）。
3. **只掛 `Scene_Change` 不夠**：第一次實跑整段登入都沒觸發它。
   加上 CDO 直讀當後備才拿得到值（後來第二次跑它有觸發，時機與時序有關 ⬜）。

## ⚠️ 方法論風險：這個 hook 會干擾它要量的東西

戰鬥中每個 5 秒視窗 **70–89 萬次**呼叫（約 **14–18 萬次/秒**），大廳也有 2.6 萬次/秒。
客戶端照常運作、沒被砍、還能被自動化操控，但：

**投射物遺失的機制是 `D = DeltaTime × CurrentNetSpeed`。hook 若拉低 FPS，
`DeltaTime` 變大 → 銀行變寬 → 遺失率下降。** 也就是說**掛著 Frida 量到的遺失率
會比沒掛時低**，兩者不可直接比較。

→ **在拿 Frida 計數取代 log 計數之前，必須先量「掛 hook 前後的 FPS」。**
若差距明顯，要改成更窄的掛點（只掛開火相關的函式，而不是所有 script 事件）。
⬜ 尚未量測。

## 🟡 `0x2234b0` 到底是不是 `ProcessRemoteFunction`

普查裡出現大量**非網路**函式（`RenderOverlays`、`PostDrawHud`、`PlayerMove`、
`PlayerCalcView`…），所以這個入口攔到的是**所有 script 事件**，不是只有 remote function。
它要嘛其實是 `ProcessEvent`，要嘛 `ProcessRemoteFunction` 對每個事件都被呼叫再提早返回。
既有日誌稱它 `ProcessRemoteFunction`，**先標 🟡，不照抄**。
（不影響計數正確性——名字過濾是對的。）
