本篇只做階段 0（唯讀分析＋下載＋出計畫），**沒有載入過任何東西，沒有碰過客戶端**。

## 1. Proxy DLL 候選

解析主安裝 `/mnt/c/Games/鐵影特攻(MetalRage Online)/data/System` 底下
`MetalRage.exe` 與所有 `*.dll` 的 import/export 表（`pefile`），
逐檔清單見 `research/2026-09-22-bridge-spike/import-table-dump.txt`，
分析見同目錄 `proxy-dll-candidates.md`。

`reg.exe query HKLM\...\KnownDLLs`（原生 64 位元清單，`KnownDLLs32` 機碼**不存在**，
見 `knowndlls-reg-dump.txt`）排除掉原生已知 DLL 後，候選裡風險最低的是
**`VERSION.dll`**：不在 KnownDLLs、只被 7 個周邊模組（語音/除錯輔助/輸入處理小工具）
用到，**不在**核心引擎/繪圖/網路那條鏈上；系統版 17 個 export 裡客戶端只用 5 個
（`GetFileVersionInfoA/W`、`GetFileVersionInfoSizeA/W`、`VerQueryValueA`），
全部單純轉發，實作面小。次選 `DINPUT8.dll`（符號更少但踩在 WinDrv 輸入鏈上）。
明確不建議：`wsock32.dll`（IpDrv 網路本線）、`d3d8/9.dll`（繪圖本線，出包＝無畫面）、
以及看起來疑似保護相關的 `ImpersonatorLib_rd.dll`／`dinterface.dll`+
`dinterface.original.dll` 依賴鏈（避免踩 AGENTS.md 的「不碰 anti-attach」紅線）。

🟡 **`MetalRage.exe` 自己的靜態 import 表幾乎是空的**（只有 2 個符號、且本身有 1 個
export），暗示 EXE 被封裝過、真正依賴在執行期動態解析，靜態分析看不到它的直接
依賴。本次候選排序是從「周邊 DLL 的 import 表」推出來的，不是 EXE 本身。
這件事本身可能值得另外找時間看，但超出本次階段 0 範圍，只記錄觀察。

## 3. frida-gadget

下載 `frida-gadget-17.18.0-windows-x86.dll`（GitHub `frida/frida` release
`17.18.0`，2026-09-09 發布），`file` 確認 `PE32 ... Intel 80386`（32 位元，非
x86_64）。版本號、下載網址、本機算的 sha256 記在
`tools/bridge/README.md`。🟡 sha256 只是自我核對（frida release 頁沒有附獨立
checksum 檔可比對），不是對上游公告值的驗證。

## 4. 階段 1 計畫
