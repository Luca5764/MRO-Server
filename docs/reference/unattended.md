# 無人值守實驗規則（Pico HID）

操作者上班不在家時，AI 透過 Pico 2 W 操作遊戲跑實驗。依據：`AGENTS.md` 硬性約束 3（2026-09-19 操作者同意）、PM 建議（2026-09-19）。工具與護欄見 `Metal Rage Online Server/tools/pico/README.md`。

## 1. 只跑事先核准的清單

- 操作者出門前核准的是**一份具體清單**，不是「授權自己找事做」。每一項要寫：
  - 實驗 ID（`U-<日期>-<序號>`）；
  - 要打開或關閉的開關；
  - 操作步驟；
  - 預期看到的畫面；
  - 停止條件。
- 需要重啟伺服器、改 DB、花遊戲內貨幣、重開客戶端的步驟，**清單上要明列**，沒列就不做。
- 清單外的發現只記錄，不動手。
- 一次只改一個變數（工作原則 7）。每個實驗 ID 都要串起四樣東西：build 事件、session log、截圖、`tools/pico/logs/actions.log`。

## 2. 無法確認就停

以下任何一種情況出現，都要：立刻停止 → 放開所有按鍵（`RESET`）→ 寫 marker → 結束這一輪。**不要嘗試自己恢復。**

- 前景視窗查不到；
- 出現鎖定畫面、UAC、Windows 更新或防火牆視窗（鎖定畫面有密碼欄，特別危險）；
- 截圖失敗；
- 畫面跟上一步預期的不符，連續 2 次；
- 客戶端行程不見了；
- 伺服器出現 EXCEPTION。

護欄工具遇到以上任何一種都會回 BLOCKED，session 轉成 halted。要繼續，必須等操作者回來重新開 session。

## 3. 證據等級

- 無人實驗的畫面證據是 AI 自己截的，標 `[SHOT]`，**不是** `[OBS]`。截圖一律拍整個遊戲視窗。
- 無人實驗得到的結論**最多標 🟡**（`[SHOT][LOG]`）。操作者看過截圖或重現一次之後才能升 ✅。
- 例外：有明確 `[DLL]` 依據，而且畫面判定毫無歧義，可以直接標 ✅，但日誌要寫明理由。

## 4. 出門前的準備（操作者）

- 電腦不能睡眠、不能鎖定畫面。這樣一來，你不在時電腦是解鎖狀態，這個風險由操作者決定接不接受。
- 伺服器、客戶端開著，停在大廳。
- 前景：`tools/win/shot.sh`（`screen.ps1` 的 `SetForegroundWindow`）實測能把遊戲從 VS Code 切回前景（2026-09-19 [TEST]；Windows 的前景鎖定規則不保證每次都成功 🟡）。每一步先截圖，再送指令；切換失敗時護欄的前景檢查照樣會擋。不用 Pico 點擊來搶前景。遊戲視窗放主螢幕，VS Code 或終端機放第二螢幕。
- 遊戲使用英文輸入法。
- 緊急停止：建立 `%USERPROFILE%\mro-pico\STOP` 檔案，或拔掉 USB 線。

## 5. 適合無人跑的候選（PM 2026-09-19 建議）

都是單機、畫面判定明確的項目：

- H1：登入後商店沒收到資料的時序實驗；
- 房間選項／optionMask 各 bit 的畫面對照；
- PvE 各地圖能不能開場的快速檢查（冒煙測試）；
- 商店各分頁截圖盤點（給 P3 價格清單用）。

戰鬥本身不自動化。
