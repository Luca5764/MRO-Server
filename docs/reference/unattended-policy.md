## 丙：一律先問操作者

- 部署或重啟測試伺服器。
- 任何 DB 變更。
- 用測試帳號以外的帳號操作。
- 花遊戲內貨幣，或永久改變帳號狀態。
- 翻線上伺服器的開關（除非該實驗的核准清單明列）。
- **任何新 runner 腳本的第一次執行**：第一次要有人在場，成功一次之後，才可以由操作者加進甲類。
  「在場」有兩種，見下面「在場的定義」。

## 在場的定義（操作者 2026-09-21 同意）

操作者原話：「我可以遠端看，也算是一種在場」。「在場」的目的是**有人能即時看到狀況並喊停**，
不是人一定要坐在電腦前。所以分兩種：

- **現場在場**：操作者在電腦前。
- **遠端在場**：**四個條件同時成立**才算數，缺一不可：
  1. 操作者**當下正在對話裡跟著這一輪**（留言後離開不算）。
  2. 每個步驟完成或 halt 時，把該步的截圖用 `SendUserFile` 傳給他，並用**一行**文字說明
     現在在哪一步。（只傳檔，AI 自己不用讀圖，省額度。）
  3. **停止詞「停」**：他在對話裡打「停」，就**立刻**寫 STOP 檔並回報已停——
     不問原因、不先把當前這一步做完。
  4. **超過 3 分鐘沒有他的回應**，就在當前步驟結束後自動停在安全點，不往下走。

**遠端在場只適用於「新動作的第一次實跑」這一條。** 丙類的其他項目（部署、重啟測試伺服器、
DB 變更、用測試帳號以外的帳號、花遊戲內貨幣、翻線上開關）照舊要操作者**明確同意**，
不因為他人在線上就自動放行。

其餘條件不變：fail-closed、只用測試帳號、非預期畫面就停不重試、崩潰不自動重開、
整輪 dead-man 25 分鐘、無人時段的結論先標 🟡。

## 丁：條件

- **啟動任何客戶端之前，先確認關閉路徑可用。**（2026-09-20 新增，PM 裁決）
  前景閘門、`Get-MetalRageWindow` 的尺寸閘門、`close_client()` 的前置條件都要先過。
  **量測用、唯讀類的任務也一樣**——不能只想著啟動。
  由來：2026-09-20 晚一個唯讀量測任務啟動了主安裝客戶端，之後發現遊戲解析度（1152x864）
  與 atlas（client 1600x1200）不符，尺寸閘門把唯一支援的關閉路徑（Pico 點擊標題列 X）擋下；
  `taskkill`／`Stop-Process` 對這個客戶端本來就被拒。結果留下一個關不掉的行程，
  雖然無害，但它佔住 `MetalRage.exe` 這個行程名，擋掉了整晚的同機雙開。
- 停止條件照舊；當掉重開每個 session 最多 3 次。
- 無人時段得到的結論一律 🟡。
- 每天早上在 `docs/HANDOFF.md` 最上面留夜間報告。
- **AI 不能自己把項目加進甲類**，只有操作者能加。

## 待辦：測試帳號（2026-09-20）

甲類要求「只用測試帳號」，但到目前為止的無人實跑用的都是操作者的 **Lucas** 帳號。要開一個專用測試帳號：
- 名稱一看就知道是測試用；
- 加進白名單，並在 `allowed-users.json` 標 `isTest`；
- 給它預設機體與裝備。

建帳號屬於 DB 變更（丙類），等操作者同意。在那之前，甲類項目照樣用 Lucas 跑，但這個狀況要在報告裡註明。
